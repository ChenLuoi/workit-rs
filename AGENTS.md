# Agent guide for workit-rs

`wk` creates one Git worktree per participating project and groups them in a task directory. Implement workspace behavior in Rust. Use Node.js or shell for project scripts. The npm launcher delegates to the same binary. Both distribution channels use the package name `workit-rs`.

## Pre-release compatibility

The project has no public release or external users. Breaking changes to commands, configuration, task records, and directory layouts are acceptable. Developers may discard their own local workspaces and initialize fresh ones. Skip legacy readers, migrations, and compatibility tests. Continue to protect local Git data and support recovery of interrupted operations in the current format. Remove this policy before the first public release.

## Run from source

Use Rust 1.94 or later, Cargo, and Git. From the repository root, run `cargo run --locked -- <args>` or `just wk <args>`. Use `just wk --help` for the command inventory and `just wk <command> --help` for its arguments.

For a manual check, run `just wk init`, then `just wk doctor`. The checkout sets `WK_WORKSPACE` to the ignored `.wk-dev/` directory through `.cargo/config.toml`. To reproduce against a different directory, use `just wk init <dir>` followed by `just wk -w <dir> status --json`. Keep automated test data in temporary directories.

## Change the implementation

| Area | Source and contracts |
| --- | --- |
| CLI | `src/main.rs` defines clap arguments and dispatch. `wk run <task> -- <program> [args...]` executes in the task directory and passes through arguments, terminal I/O, and exit status. |
| Workspace | `src/workspace.rs` owns the CLI-managed `wk.yaml` manifest. `add` / `clone` requires a fresh name and destination, allows repeated URLs, and persists the name, URL, and concrete task base. `sync` restores missing clones and fetches existing ones. |
| Task lifecycle | `tasks/<task>/` is the common editor and harness working directory. Each `<project>/` child is a Git worktree. Shared resources live alongside them. Resume from the commits in `.wk/tasks/<task>.json`. Before closing, check every member for local changes, untracked files, and ignored files. Remove the registered worktrees, then the entire task directory. Preserve the branches and archived record. |
| Git and reporting | `src/git.rs` invokes system Git. `src/report.rs` implements status and diagnostics. Default status uses local Git data. `--fetch` explicitly refreshes it. |

Keep ordinary clones in `repos/` for browsing. Start every development task with `wk start`; edits, builds and commits belong in its linked worktrees. Commands using a reference clone must check it for local changes. Project removal must also protect open tasks, external worktrees and commits absent from locally known origin branches.

Edit the workspace or task instructions generated by `wk` in `src/workspace.rs` or `src/tasks.rs`, respectively. This root file governs development of the tool itself.

## Verify a change

- Exercise CLI behavior in `tests/cli.rs` using the built binary and temporary local Git repositories. Run a single scenario with `cargo test --locked --test cli <test_name>`.
- Run `just check` for formatting, Clippy, and tests. The equivalent commands are `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, and `cargo test --locked`.
- For interactive `add`, `clone`, or `start` changes, run `just smoke-interactive` on Linux or macOS with Node.js 20+ and the system `script` utility. It builds the debug binary, drives the prompts against local repositories, and checks the selected commits in each worktree.
- For npm launcher or packaging changes, use Node.js 20 or later, npm, and Bash. Run `just smoke-npm` to build and exercise both local tarballs. To inspect the crate contents before committing, use `cargo package --locked --allow-dirty --list`.

## Documentation and release

Keep user-facing Markdown in matched English (`NAME.md`) and Simplified Chinese (`NAME.zh-CN.md`) files with reciprocal relative links. Update both when commands or examples change. Keep this agent guide in English only.

For a release, align the versions in `Cargo.toml`, `Cargo.lock`, `package.json`, and its optional dependencies. Run `node scripts/npm-package.mjs check`. Manual dispatch of the Release workflow builds and packages every target. Pushing a matching `v<version>` tag triggers publication using `CARGO_REGISTRY_TOKEN` and `NPM_TOKEN` from the GitHub `release` environment.
